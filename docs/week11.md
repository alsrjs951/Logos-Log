## 📌 강의 개요
* **주제:** Trunk-Based Development (트렁크 기반 개발 전략 및 실천 가이드)
* **목표:** TBD 핵심 개념 이해, Git Flow와의 비교 분석, CI/CD 파이프라인 연계, 팀 협업 강화 방법 학습

## 🌳 Trunk-Based Development (TBD) 핵심 원칙
TBD는 복잡성을 줄이고 배포 속도를 높이는 최적의 협업 전략으로, "Commit early, commit often"을 지향합니다.

1. **단일 메인 브랜치 (Single Trunk):** `develop` 같은 장기 유지 브랜치를 두지 않고 오직 `main` (또는 `trunk`) 단일 브랜치만 진실 공급원(Source of Truth)으로 관리합니다.
2. **짧은 생명주기 브랜치:** 기능(Feature) 브랜치는 생성 후 **24시간 이내**에 메인 브랜치로 병합 및 삭제되어야 합니다.
3. **작은 커밋, 자주 통합:** 거대한 변경사항 대신 작고 독립적인 단위로 쪼개어 하루에도 여러 번 메인 브랜치에 통합합니다.
4. **Feature Flags 활용:** 미완성 기능도 메인에 병합하되, 사용자에게 노출되지 않도록 플래그로 감싸 배포(Deploy)와 출시(Release)를 분리합니다.
5. **빠른 피드백 (CI 자동화):** 변경 사항 병합 시 즉각적으로 자동화된 CI 파이프라인(테스트)이 실행되어 버그를 초기에 발견합니다.

## ⚖️ TBD vs Git Flow 비교

| 비교 항목 | 전통적 Git Flow | Trunk-Based Development (TBD) |
| :--- | :--- | :--- |
| **브랜치 수** | 많음 (Develop, Release, Feature, Hotfix) | 적음 (Main + Short-lived Feature) |
| **브랜치 수명** | 장기 (수일 ~ 수주) | 단기 (24시간 이내 권장) |
| **통합 빈도** | 낮음 (기능 완성 시점) | 높음 (하루에도 수십 번) |
| **병합 충돌** | 빈번함 / 복잡함 (Merge Hell 위험) | 드물거나 간단함 (즉시 해결 가능) |
| **배포 속도** | 느림 (릴리스 주기에 종속) | 빠름 (Continuous Delivery 최적화) |

## 🛑 피해야 할 안티패턴 (Anti-Patterns)
* **장기 Feature 브랜치:** 며칠/몇 주간 브랜치를 유지하면 `Merge Hell(병합 충돌)`이 발생하므로 하루 단위로 작업을 쪼개야 합니다.
* **Feature Flag 미정리:** 배포 완료된 플래그를 방치하면 '좀비 코드(기술 부채)'가 되므로, 100% 롤아웃 후 즉시 삭제해야 합니다.
* **거대한 PR (Mega PR):** 수천 줄의 코드는 리뷰가 불가능하므로 `500줄 단위`로 분할하여 PR을 올려야 합니다.

## 🚀 [중요] 실습 과제 (Hands-on Labs)

TBD의 핵심 프로세스를 경험하고 개발 환경을 구축하기 위한 4개의 미션입니다.

### 📝 Mission 01: TBD 워크플로우 실천
* 반드시 `main` 브랜치에서 작업을 시작합니다.
* 2~3시간 분량의 작은 기능을 구현합니다.
* PR 생성 및 동료 리뷰 후 즉시 병합합니다.
* 위 과정을 하루 동안 최소 3회 반복합니다.

### 📝 Mission 02: Feature Flags 도입
* 간단한 Feature Flag 시스템을 구현하거나 라이브러리를 설치합니다.
* 미완성 기능을 Flag로 감싸서 사용자에게 숨깁니다.
* 기능이 완성되지 않았더라도 코드를 `main`에 병합합니다.
* 개발 완료 후 Flag를 활성화하여 배포합니다.

### 📝 Mission 03: Metrics Dashboard
* 팀의 TBD 건강도를 측정할 핵심 지표(브랜치 수명, PR 크기, 일일 병합 빈도)를 정의하고 데이터를 수집합니다.
* 간단한 대시보드를 구축하여 팀원들과 공유합니다.
* 데이터에 기반한 개선 목표(예: 브랜치 수명 < 1일)를 설정합니다.

### 📝 Mission 04: CI/CD 최적화
* GitHub Actions 워크플로우를 작성합니다.
* '브랜치 나이 체크 스크립트'를 CI 파이프라인에 추가합니다.
* PR 크기가 특정 라인 수(예: 500줄)를 넘으면 경고를 띄우도록 설정합니다.
* *(선택)* Dependabot 등 봇이 올린 PR은 테스트 통과 시 자동 병합되도록 설정합니다.
