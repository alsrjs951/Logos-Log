## 📊 소프트웨어 개발의 3대 메트릭

### 1. DORA Metrics (소프트웨어 전달 성능 4대 지표)
* **Lead Time for Changes:** 코드 커밋부터 프로덕션 환경에 배포되기까지 걸리는 총 소요 시간 (속도 지표).
* **Deployment Frequency:** 프로덕션 환경에 코드를 성공적으로 배포하는 빈도 (속도 지표).
* **Mean Time to Recovery (MTTR):** 장애 발생 시점부터 정상 상태로 완전히 복구될 때까지의 평균 시간 (안정성 지표).
* **Change Failure Rate:** 프로덕션 배포 중 실패하거나 긴급 롤백/패치가 필요한 변경 사항의 비율 (안정성 지표).

### 2. Flow Metrics (작업 흐름 측정)
* **Cycle Time:** 작업이 실제로 시작된 시점(In Progress)부터 사용자에게 전달(Done)될 때까지 걸리는 시간.
* **WIP (Work In Progress):** 동시에 진행 중이지만 아직 완료되지 않은 작업의 수.
* **Throughput (처리량):** 특정 기간 동안 완료된 작업 항목의 총 개수.
* **리틀의 법칙 (Little's Law):** 처리량이 일정할 때, 진행 중인 작업(WIP)을 줄이면 사이클 타임(Cycle Time)이 단축됩니다.

### 3. 코드 품질 메트릭
* **Code Coverage:** 소스 코드가 테스트된 비율. 최소 70%, 권장 80-90% 수준을 유지해야 합니다.
* **Technical Debt (기술 부채):** 품질을 희생하여 빠른 배포를 선택했을 때 발생하는 미래의 유지보수 비용.
* **Code Churn (코드 변동률):** 코드가 추가, 수정, 삭제되는 빈도. 릴리스 직전 높은 변동률은 코드 불안정성을 의미합니다.

## 🚀 지속적 개선 프로세스
1. **현상 측정 (Measure):** 현재 상태(기준선)를 데이터로 정확히 파악합니다.
2. **목표 설정 (Set Goals):** 구체적이고 달성 가능한 SMART 원칙 기반의 개선 목표를 수립합니다.
3. **실험 (Experiment):** 가설을 세우고 파이프라인 변경이나 테스트 도입 등의 실험을 적용합니다.
4. **모니터링 (Monitor):** 대시보드(Grafana 등)와 알림을 통해 결과를 지속해서 추적하고 조치합니다.

## 📝 1주차 실습 과제 상세 내역
다음은 이번 주차에 완료해야 할 3가지 필수 과제입니다.

### 과제 1: DORA Metrics 수집 자동화
* **목표:** GitHub Actions로 지표 자동 수집 및 리포팅 파이프라인 구축.
* **요구사항:**
  1. Pull Request 및 Deployment 이벤트에 반응하는 `.yml` 워크플로우를 작성해야 합니다.
  2. Lead Time, 배포 빈도, MTTR, 변경 실패율 등 4가지 지표를 자동 계산하는 로직을 구현해야 합니다.
  3. 데이터를 JSON 형식으로 Artifact에 저장하거나 별도 브랜치에 커밋해야 합니다.
  4. 매주 수집된 데이터를 요약해 Issue나 Slack으로 전송하는 잡(Job)을 추가해야 합니다.
* **제출 형식:**
  * GitHub 리포지토리 URL 제출
  * 워크플로우 파일(`.github/workflows/metrics.yml`) 포함
  * 실행 성공 로그 스크린샷 1부
  * `README.md` 내에 구현 방법 간략 기술

### 과제 2: 메트릭 대시보드 구축
* **목표:** 수집된 데이터를 시각화하여 실시간 모니터링 환경 구성.
* **요구사항:**
  1. GitHub API (REST 또는 GraphQL)를 활용해 주기적으로 데이터를 수집해야 합니다.
  2. Grafana, Chart.js, D3.js 등의 라이브러리로 주요 지표를 실시간 차트 형태로 구현해야 합니다.
  3. `README.md` 상단에 빌드 성공 여부, 커버리지 등을 보여주는 실시간 뱃지를 추가해야 합니다.
* **제출 형식:**
  * 대시보드 접속 URL 또는 스크린샷
  * 구현 코드 (Frontend/Backend 리포지토리)
  * 사용된 API 및 도구 명세서
  * `README.md`에 부착된 뱃지 확인 링크

### 과제 3: 개선 계획 수립
* **목표:** 베이스라인 데이터를 분석하여 구체적인 개선 목표와 로드맵 작성.
* **요구사항:**
  1. 현재 프로젝트의 지표 데이터를 수집하고 병목 지점을 분석해야 합니다.
  2. SMART 원칙에 기반하여 개선 목표를 설정해야 합니다.
  3. 목표 달성을 위한 도구 도입 및 테스트 전략 등을 포함한 액션 플랜을 작성해야 합니다.
* **제출 형식:**
  * 개선 계획 보고서 (PDF 또는 Markdown 형식)
  * 현재 메트릭 상태 스크린샷 첨부
  * 예상 성과 및 일정표(Roadmap)
  * GitHub 저장소 내에 `IMPROVEMENT.md` 파일로 업로드하여 제출
