## 📌 5주차 강의 개요 및 오픈소스 핵심 가치
* **강의 주제:** 오픈소스와 이너소스가 소프트웨어 전달 성능에 미치는 영향.
* **오픈소스(OSS)란:** 소스 코드가 공개되어 누구나 자유롭게 사용, 수정, 배포할 수 있는 소프트웨어를 의미합니다.
* **오픈소스의 5대 핵심 가치:**
    * **투명성:** 소스 코드 공개를 통해 전 세계 개발자들이 검토하고 취약점을 조기 발견하여 신뢰를 구축합니다.
    * **협업:** 전 세계 수백만 명의 개발자가 협력하며 다양한 관점으로 문제를 빠르게 해결합니다.
    * **혁신:** 제약 없는 실험과 빠른 프로토타이핑을 통해 산업 발전을 가속합니다.
    * **품질:** "많은 눈이 있으면 모든 버그는 얕아진다(Linus's Law)"는 원칙에 따라 높은 안정성을 확보합니다.
    * **커뮤니티:** 지식 공유, 멘토링, 네트워킹을 통한 지속 가능한 생태계를 형성합니다.

## ⚖️ 오픈소스 라이선스 분류
오픈소스 라이선스는 소프트웨어의 상업적 사용, 수정 권한, 재배포, 소스 공개 의무 등을 법적으로 정의합니다.
* **Permissive (관대한 라이선스):** 상업적 이용과 수정, 배포 제약이 가장 적으며 소스 공개 의무가 없습니다.
    * 대표 사례: MIT, Apache 2.0, BSD.
* **Copyleft (강한 공유 라이선스):** 수정된 코드를 배포할 경우 전체 소스 코드 공개 의무가 발생하는 전염성 라이선스입니다.
    * 대표 사례: GPL, LGPL, AGPL.
* **기타 라이선스:** 파일 단위로 공개 의무가 적용되는 하이브리드 라이선스인 MPL, 비소프트웨어 저작물(문서, 미디어 등)에 사용되는 CC(Creative Commons)가 있습니다.

## 🏢 이너소스 (Inner Source)와 DORA 성과 지표
* **이너소스 개념:** 오픈소스의 자발적 기여와 협업 방식을 조직 내부에 적용하여 부서 간 장벽을 허무는 개발 문화입니다. 코드는 조직 내부에만 공개되며 외부에는 비공개로 유지됩니다.
* **소프트웨어 전달 성능(DORA) 개선 효과:** 오픈소스나 이너소스에 기여하는 조직은 비기여 조직에 비해 다음과 같은 높은 성과를 보여줍니다.
    * **Lead Time for Changes:** 배포까지 소요 시간 단축 (1.75배 더 빠름).
    * **Deployment Frequency:** 배포 빈도 증가 (1.5배 더 자주 배포).
    * **Time to Restore:** 장애 복구 속도 향상 (1.5배).
    * **Change Failure Rate:** 배포 실패율 유의미하게 감소 (-20%).

## 🚀 [중요] 5주차 실습 과제 상세 내역

이번 주차에는 총 4개의 실습 과제가 부여되었으며, 세부 내용은 다음과 같습니다.

### 📝 과제 1: 오픈소스 프로젝트 생성
* **목표:** 자신만의 오픈소스 프로젝트를 시작하고 필수 요소를 갖춥니다.
* **수행 체크리스트:**
    * GitHub Public 레포지토리 생성 (적절한 이름과 설명 포함).
    * 필수 문서 작성 (MIT 라이선스 적용 및 `README.md` 작성).
    * 기여 가이드(`CONTRIBUTING.md`) 및 행동 강령(`CODE_OF_CONDUCT.md`) 파일 추가.
    * 첫 릴리스 배포 (버전 태그 `v1.0.0` 생성 및 릴리스 노트 작성).
* **제출 형식:** GitHub 레포지토리 URL 제출 (LMS 업로드).
* **제출 기한:** 다음 주 수업 시작 전까지.

### 📝 과제 2: 오픈소스 기여
* **목표:** 실제 오픈소스 프로젝트의 이슈를 찾아 해결하고 PR을 제출하는 전체 과정을 경험합니다.
* **수행 체크리스트:**
    * 'good first issue' 레이블이 붙은 이슈 찾기.
    * 선택한 프로젝트를 Fork & Clone 하기.
    * 새 브랜치를 생성하여 코드를 수정하고, 테스트 통과 후 커밋하기.
    * 템플릿에 맞춰 상세하게 Pull Request(PR) 제출하기.
    * 메인테이너의 피드백(리뷰)에 대응하고 최종 머지(Merge) 확인하기.
* **제출 형식:** PR 링크 제출 (Merged 또는 Open 상태).
* **제출 기한:** 학기 말 프로젝트 발표 전까지.

### 📝 과제 3: 라이선스 분석
* **목표:** 실제 성공한 오픈소스 프로젝트들의 라이선스 전략을 분석하고 인사이트를 도출합니다.
* **수행 체크리스트:**
    * 다양한 분야의 유명 오픈소스 프로젝트 5개 선정.
    * 각 프로젝트의 `LICENSE` 파일을 확인하여 라이선스 종류 파악.
    * 해당 라이선스를 선택한 이유(기업 전략, 커뮤니티 보호 등) 분석.
    * 조사 내용과 분석 결과, 시사점을 포함한 보고서 작성.
* **제출 형식:** PDF 보고서 제출 (자유 양식, 2-3페이지 / LMS 제출).
* **제출 기한:** 다음 주 수업 시작 전까지.

### 📝 과제 4: Inner Source 계획
* **목표:** 조직 내 오픈소스 문화를 도입하기 위한 전략과 실행 계획을 수립합니다.
* **수행 체크리스트:**
    * 조직 내 이너소스 도입 대상 부서나 시범 프로젝트를 선정하고 적용 범위 정의.
    * 도입 시 예상되는 이점(기대 효과) 및 도전 과제(잠재적 장애요인) 분석.
    * 문화 조성, 도구 도입 등 단계별 실행 로드맵 작성.
    * 성공 여부를 측정할 핵심 성과 지표(KPI) 설정.
* **제출 형식:** PDF 보고서 제출 (3-5 pages / LMS 업로드).
* **제출 기한:** 다음 주 수업 시작 전까지.
