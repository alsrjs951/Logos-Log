제공해주신 '린 제품 개발과 린 스타트업(Lean Startup)' 강의 자료의 핵심 내용을 마크다운 문법으로 정리해 드립니다. 요청하신 실습 과제 부분은 특히 상세하게 작성했습니다.

## 🚀 린 스타트업 (Lean Startup) 핵심 요약

린 스타트업은 불확실한 시장 환경에서 낭비를 줄이고 빠르게 학습하여 성공 확률을 높이는 현대적 제품 개발 방법론입니다.

* **핵심 철학:** "Fail fast, Learn faster" (빠르게 실패하고 더 빨리 배우기).
* **5가지 핵심 원칙:** BML 사이클, 검증된 학습, MVP 구축, 혁신 회계, 방향 전환(Pivot) 또는 고수(Persevere).

### 1. Build-Measure-Learn (BML) 사이클
아이디어를 제품으로 구현하고 데이터를 측정하여 학습하는 지속적인 피드백 루프입니다.
* **BUILD (구축):** 가설 검증을 위한 최소 기능(MVP)을 빠르게 구현.
* **MEASURE (측정):** 고객 반응을 정량적 데이터로 수집 및 분석.
* **LEARN (학습):** 데이터를 통해 가설의 참/거짓을 판별하고 다음 방향을 결정.

### 2. MVP (Minimum Viable Product, 최소 기능 제품)
최소한의 노력과 비용으로 고객에 대한 검증된 학습을 최대화하는 전략입니다.
* 완벽한 제품의 부품(예: 바퀴 -> 뼈대 -> 자동차)을 순차적으로 만드는 것이 아니라, 아주 단순하더라도 즉시 가치를 제공(예: 스케이트보드 -> 스쿠터 -> 자동차)해야 합니다.
* **성공 사례:** 복잡한 개발 대신 3분 데모 비디오로 수요를 검증한 **Dropbox**, 재고와 창고 없이 동네 신발 가게에서 직접 구매해 배송했던 **Zappos**.

### 3. 혁신 회계 (Innovation Accounting)
전통적인 재무 지표가 아닌 스타트업의 성장을 측정하는 성과 지표 시스템입니다.
* **허영 지표 (Vanity Metrics) 피하기:** 누적 가입자 수, 단순 페이지뷰 등 기분은 좋게 하지만 의사결정에 도움을 주지 않는 지표.
* **실행 가능 지표 (Actionable Metrics) 집중:** 실제 활성도(DAU/MAU 비율), 재방문율 등 다음 행동을 유도할 수 있고 실제 비즈니스 상태를 반영하는 지표.

### 4. Pivot vs Persevere (방향 전환 vs 유지)
제품-시장 적합성(PMF)이 부족하거나 성장이 정체되었을 때, 근본적인 가설을 수정하되 비전은 유지하는 전략적 방향 전환입니다.
* **Pivot 유형:** 단일 기능에 집중하는 Zoom-in, 더 큰 플랫폼으로 확장하는 Zoom-out, 타겟 고객 변경, 플랫폼 변경 등.

### 5. 실험 자동화 및 GitHub 활용
가설 관리부터 메트릭 수집까지 개발 프로세스를 효율적으로 관리할 수 있습니다.
* **도구 연동:** GitHub Issues(가설 관리), GitHub Projects(칸반 보드를 통한 실험 단계 추적), GitHub Actions(메트릭 자동 수집), Feature Flags(A/B 테스트 및 타겟팅 배포).

## 📝 주차별 핵심 실습 과제 (Assignments)

린 스타트업 방법론을 체화하기 위해 수행해야 하는 4가지 필수 실습 과제입니다.

### 과제 1: MVP 구축
1. 해결하고자 하는 문제 정의, 아이디어 선정 및 핵심 가설 작성
2. 핵심 기능만 포함하여 1주일 안에 작동 가능한 MVP 구축
3. 최소 10명의 잠재 고객을 대상으로 사용성 테스트 진행
4. 사용자 피드백 수집 및 초기 가설 검증 결과 분석

### 과제 2: A/B 테스팅
1. 기존 앱이나 웹사이트에 개선을 위한 2가지 변형(Variant) 구현
2. Feature Flag를 사용하여 사용자 그룹별 노출 제어 설정
3. 2주간 실제 트래픽을 통해 전환율 등 핵심 메트릭 데이터 수집
4. 통계적 유의성 검증을 통해 승자 버전을 결정하고 배포

### 과제 3: Metrics Dashboard
1. GitHub Issues를 활용하여 실험 가설 및 성공 지표 체계적 관리
2. GitHub Projects 보드로 실험의 진행 단계(Backlog~Shipped) 추적
3. GitHub Actions를 연동하여 주요 메트릭 데이터 자동 수집 파이프라인 구축
4. 매주 월요일 주요 지표 변화를 보여주는 주간 리포트 자동 생성

### 과제 4: Pivot 시뮬레이션
1. 현재 제품이 시장 적합성을 찾지 못해 성장이 정체된 가상 실패 시나리오 작성
2. 가상의 사용자 데이터와 피드백을 분석하여 Pivot 여부를 데이터 기반으로 결정
3. Zoom-in, Zoom-out 등 적절한 Pivot 유형을 선택하여 새로운 방향 정의
4. 변경된 방향에 맞춘 새로운 가설 수립 및 2주 단위 실행 계획 수립
