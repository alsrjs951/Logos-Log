## 📌 강의 개요 및 핵심 목표
* **과목명:** AI Open Source Software (3주차)
* **담당 교수:** 전세진 교수
* **학습 목표:** Pull Request 기반의 협업 프로세스 이해, 건설적인 코드 리뷰 수행, Git 브랜치 전략 선택, 협업 베스트 프랙티스 실천.
* **협업의 중요성 (Bus Factor):** 특정 인원에게 지식이 집중되는 단일 실패 지점(SPOF)을 피하고, 지식을 공유하여 프로젝트의 안정성을 높여야 합니다.

## 🌿 Git 협업 워크플로우 및 브랜치 전략
* **Git Flow (전통적):** 대규모 팀 및 정기적인 릴리스에 적합하며 `main`, `develop`, `feature`, `release`, `hotfix` 등으로 환경을 명확히 분리합니다.
* **GitHub Flow (현대적/권장):** 지속적 배포(CI/CD)에 최적화된 단순한 구조로, `main` 브랜치는 항상 배포 가능한 상태를 유지해야 합니다.
* **브랜치 네이밍 컨벤션:** `feature/`(기능), `fix/`(버그 수정), `docs/`(문서), `refactor/`(리팩토링), `test/`(테스트), `chore/`(빌드/설정) 등 목적을 명확히 표시합니다.

---

## 💡 Pull Request(PR) 및 코드 리뷰 가이드
* **좋은 PR의 조건:** 명확한 제목, 상세한 Description 작성, PR 템플릿(`.github/pull_request_template.md`) 활용.
* **PR 크기 (Golden Rule):** 100~200줄 이내의 Small PR을 적극 권장하며, 리뷰가 1시간 이내에 완료될 수 있게 작은 단위로 자주 올려야 합니다.
* **건설적인 코드 리뷰:**
    * 비난이 아닌 구체적인 제안과 대안을 제시합니다.
    * 리뷰 코멘트 태그 활용: `[MUST]`(필수 수정), `[SHOULD]`(강력 권장), `[NITS]`(사소한 제안), `[IDEA]`(아이디어 제안), `[QUESTION]`(질문), `[PRAISE]`(칭찬).
    * 리뷰는 동료의 작업이 블로킹되지 않도록 24시간 이내에 완료해야 합니다.

---

## ⚙️ 자동화 및 코드 품질 관리
* **자동화된 코드 리뷰 (CI/CD):** GitHub Actions를 통해 Lint 코드 검사, 단위 테스트(`npm test`), 보안 스캔 등을 자동화합니다.
* **CODEOWNERS:** `.github/CODEOWNERS` 파일을 설정하여 특정 디렉토리/파일 변경 시 책임자(리뷰어)를 자동으로 할당합니다.
* **커밋 메시지 컨벤션 (Conventional Commits):** `<type>(<scope>): <subject>` 구조를 따르며, 기계와 사람 모두가 읽기 쉽게 작성합니다.
* **Protected Branches (브랜치 보호):** `main` 브랜치에 직접 푸시를 제한하고, PR 리뷰와 Status Check(CI 통과)를 필수로 요구하도록 설정합니다.

## 🚀 [실습 과제] 상세 내용 정리

요청하신 3주차 실습 과제(Hands-on Labs) 4가지를 정확히 정리한 내용입니다.

### 📝 실습 과제 1: GitHub Flow (예상 소요 시간: 20분)
Feature 브랜치 전략을 사용하여 안전하게 코드를 변경하고 PR을 통해 병합하는 전체 과정을 실습합니다.
1. **Feature 브랜치 생성:** 메인 브랜치에서 새로운 작업 브랜치를 생성 (`git checkout -b feature/login-page`).
2. **코드 변경 및 커밋:** 의미 있는 단위로 작업을 수행하고 Conventional Commits 규칙을 준수하여 커밋.
3. **Pull Request 생성:** 코드를 푸시한 후 웹 인터페이스에서 템플릿에 맞춰 PR 설명을 작성.
4. **자체 리뷰 및 체크리스트:** 리뷰어 지정 전 스스로 코드를 검토하고 PR 체크리스트 완료.
5. **CI 통과 확인:** 자동화된 테스트와 Lint 검사가 통과되었는지 확인.

### 📝 실습 과제 2: 코드 리뷰 (예상 소요 시간: 30분)
동료의 코드를 리뷰하며 품질을 개선하고 건설적인 피드백 문화를 경험합니다.
1. **최소 3개의 PR 리뷰:** 현재 오픈되어 있는 다른 팀원의 PR 중 최소 3개를 선택하여 리뷰 진행.
2. **건설적인 피드백 제공:** 단순한 질문보다는 대안을 제시하거나 의도를 파악하는 문제 해결 중심의 대화 유도.
3. **리뷰 태그 시스템 활용:** `[MUST]`, `[SHOULD]`, `[NITS]` 태그를 사용하여 피드백의 중요도 명시.
4. **칭찬도 포함하기:** 잘 작성된 코드나 기발한 아이디어에는 `[PRAISE]` 태그로 칭찬 남기기.

### 📝 실습 과제 3: 자동화 설정 (예상 소요 시간: 25분)
GitHub의 자동화 기능과 정책을 통해 코드 품질을 보장하는 환경을 구축합니다.
1. **PR 템플릿 생성:** 프로젝트 루트에 `.github/pull_request_template.md`를 생성하여 팀 리뷰 표준 정립.
2. **CODEOWNERS 설정:** 특정 디렉토리/파일의 책임자를 지정해 리뷰 요청 자동화.
3. **Automated Checks 작성:** GitHub Actions를 활용해 CI 워크플로우(Lint, Test) 파일(`.github/workflows/ci.yml`) 생성.
4. **Branch Protection 설정:** `main` 브랜치에 직접 푸시를 막고, PR 리뷰 및 Status Check 통과를 강제하도록 보호 규칙 적용.

### 📝 실습 과제 4: 협업 문서 작성 (예상 소요 시간: 30분)
팀의 원활한 협업을 위한 규칙과 가이드라인을 문서화하여 저장소에 공유합니다.
1. **`CONTRIBUTING.md` 작성:** 프로젝트 기여 가이드 파일을 생성하고 개발 환경 설정 및 이슈 템플릿 정보 작성.
2. **브랜치 전략 문서화:** 팀이 사용할 브랜치 전략(Git Flow 등)과 명명 규칙(`feature/*`, `fix/*` 등) 도식화.
3. **코드 리뷰 가이드라인:** 리뷰어가 중점적으로 봐야 할 체크리스트와 태그 사용법 정의.
4. **커밋 메시지 컨벤션 문서:** Conventional Commits 등 팀이 따를 커밋 메시지 형식을 예시와 함께 명시.
