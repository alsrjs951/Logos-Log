# Logos-Log 발표 스크립트

이 문서는 Logos-Log를 포트폴리오, 졸업작품, 수업 발표에서 소개할 때 사용할 수 있는 한국어 발표 스크립트입니다. 그대로 읽어도 어색하지 않도록 구성하되, 실제 발표에서는 말투에 맞게 조금 줄여 사용하면 됩니다.

## 3분 발표 스크립트

안녕하세요. 제가 만든 프로젝트는 **Logos-Log**, 학술 기반 RAG를 활용한 의미 탐구 저널링 플랫폼입니다.

이 프로젝트는 단순히 일기를 저장하거나 감정에 공감하는 챗봇을 만드는 것이 아니라, 사용자의 고민을 심리학 연구 발췌와 연결해 더 근거 있는 자기 성찰을 돕는 것을 목표로 합니다.

문제의식은 여기서 시작했습니다. 요즘 많은 저널링 앱이나 상담형 챗봇은 사용자가 힘든 이야기를 하면 공감 문장을 잘 만들어줍니다. 하지만 그 답변이 어떤 근거에서 나왔는지 확인하기 어렵고, 때로는 그럴듯하지만 일반적인 조언에 머무릅니다. 저는 사용자가 자기 삶의 의미나 가치에 대해 고민할 때, 단순 위로보다 조금 더 신뢰할 수 있는 근거와 질문이 필요하다고 봤습니다.

그래서 Logos-Log는 긍정심리학, 의미치료, 자기결정성이론, CBT 관련 논문을 수집하고, PDF를 전처리한 뒤 청크 단위로 임베딩해 MongoDB Atlas Vector Search에 저장합니다. 사용자가 고민을 입력하면 시스템은 질문을 영어 학술 검색 표현으로 확장하고, 벡터 검색으로 관련 연구 발췌를 찾습니다. 이후 재랭킹과 주변 청크 확장을 거쳐 답변 생성에 사용할 문맥을 구성합니다.

중요하게 신경 쓴 부분은 **정직한 근거 표시**입니다. 이 앱은 검색된 발췌를 논문 전체 요약처럼 보여주지 않습니다. UI에서도 `논문 전체 요약`이 아니라 `근거 발췌`라고 표시하고, 사용자는 인용 배지, 출처 카드, 출처 모달을 통해 어떤 문장이 어떤 연구 발췌와 연결되는지 확인할 수 있습니다.

기술적으로는 처음에 하이브리드 검색도 검토했지만, 평가 결과 `$text` 하이브리드/RRF가 vector-only보다 낮게 나왔습니다. 그래서 프로덕션 검색은 MongoDB `$vectorSearch` 기반으로 유지했습니다. 대신 청크 메타데이터, 페이지/섹션 보존, 주변 청크 확장, multi-query vector retrieval, 평가 trace를 개선했습니다.

평가도 함께 진행했습니다. 승인 기준으로 삼은 평가 실행에서 Context Precision은 `0.813`, Context Recall은 `0.767`까지 올라 검색 지표는 목표를 통과한 적이 있습니다. 다만 Faithfulness는 `0.828`로 목표인 `0.90`에는 아직 도달하지 못했습니다. 그래서 verifier나 claim-checker 같은 실험도 해봤지만, 전체 평가에서 안정적으로 개선되지 않아 기본값으로 켜지는 않았습니다.

이 프로젝트에서 보여주고 싶은 핵심은 단순히 RAG를 붙였다는 점이 아닙니다. 검색 방식의 성능을 평가하고, 낮게 나온 방법은 과감히 제외하고, UI 표현도 시스템이 실제로 보장할 수 있는 범위 안에서 정직하게 바꿨다는 점입니다.

앞으로의 개선 방향은 Faithfulness입니다. 특히 답변 문장 단위로 근거가 실제로 충분한지 확인하고, 근거가 약한 문장은 더 조심스럽게 표현하도록 만드는 것이 다음 목표입니다.

## 30초 데모 멘트

이제 실제 채팅 화면에서 짧게 보여드리겠습니다.

예를 들어 `성과가 없으면 제가 가치 없는 사람처럼 느껴져요.`라고 입력하면, Logos-Log는 사용자의 고민을 학술 검색에 적합한 표현으로 확장하고 관련 연구 발췌를 검색합니다.

답변에는 인용 배지가 붙어 있고, 이 배지를 누르면 해당 문장이 어떤 근거와 연결되는지 볼 수 있습니다. 아래의 `근거 발췌` 영역을 열면 논문 제목, 저자/연도, 섹션, 페이지, 청크 정보도 확인할 수 있습니다.

여기서 중요한 점은 이 화면이 논문 전체 요약을 보여주는 것이 아니라, 실제 검색된 발췌와 주변 문맥을 근거로 답변한다는 점입니다. 그래서 사용자는 답변을 무조건 믿는 것이 아니라, 근거를 함께 확인하면서 성찰할 수 있습니다.

## 1분 압축 버전

Logos-Log는 사용자의 고민을 심리학 논문 발췌와 연결해 근거 있는 성찰 질문을 제공하는 RAG 저널링 플랫폼입니다.

기존 저널링 챗봇은 공감 문장은 잘 만들지만, 그 조언이 어떤 연구 근거에서 나왔는지 확인하기 어렵습니다. Logos-Log는 논문 PDF를 전처리하고, 청크 임베딩을 MongoDB Atlas Vector Search에 저장한 뒤, 사용자 질문과 관련 있는 연구 발췌를 찾아 답변에 인용으로 연결합니다.

프로덕션 검색은 vector-only로 유지했습니다. `$text` 하이브리드 검색도 실험했지만 평가에서 더 낮게 나왔기 때문입니다. 대신 multi-query vector retrieval, 재랭킹, 주변 청크 확장, 메타데이터 기반 출처 표시를 개선했습니다.

승인 기준으로 삼은 평가 실행에서 Context Precision `0.813`, Context Recall `0.767`을 기록해 검색 품질은 목표를 통과한 적이 있습니다. 다만 Faithfulness는 `0.828`로 아직 개선 대상입니다. 그래서 이 프로젝트는 기능 구현뿐 아니라, 평가 결과를 바탕으로 무엇을 기본값으로 둘지 결정한 RAG 시스템이라는 점에 의미가 있습니다.

## 발표 중 강조할 문장

- “이 프로젝트는 사용자의 고민을 그럴듯한 위로가 아니라 확인 가능한 연구 발췌와 연결하는 데 초점을 둡니다.”
- “하이브리드 검색은 좋아 보였지만, 실제 평가에서 vector-only보다 낮아 프로덕션 기본값에서 제외했습니다.”
- “UI에서 `논문 전체 요약`이 아니라 `근거 발췌`라고 표현한 이유는 시스템이 실제로 보장할 수 있는 범위를 넘지 않기 위해서입니다.”
- “검색 지표는 목표를 통과한 적이 있지만, Faithfulness는 아직 병목으로 남아 있고 다음 개선 목표입니다.”
- “단순 구현보다 평가, 실패한 실험의 제외, 정직한 UX 표현까지 포함한 RAG 개선 과정을 보여주고 싶었습니다.”

## 예상 질문 답변

### 왜 하이브리드 검색을 쓰지 않았나요?

처음에는 벡터 검색과 키워드 검색을 결합한 하이브리드 검색이 더 좋을 것이라고 예상했습니다. 하지만 30개 평가 케이스 기준으로 `$text` 하이브리드/RRF가 vector-only보다 낮게 나왔습니다. 그래서 프로덕션에서는 평가 결과가 더 좋은 vector-only를 유지하고, 하이브리드는 실험 경로로만 남겼습니다.

### 논문 전체를 읽고 답변하는 건가요?

아닙니다. 현재 시스템은 논문 전체를 사람이 읽듯 종합하는 방식이 아니라, 검색된 연구 발췌와 주변 청크를 근거로 답변합니다. 그래서 UI에서도 `논문 전체 요약`이 아니라 `근거 발췌`라고 표현합니다.

### 가장 어려웠던 부분은 무엇인가요?

RAG에서 검색만 잘하면 끝나는 것이 아니라, 답변이 검색된 근거를 넘어 말하지 않게 만드는 부분이 어려웠습니다. 실제 평가에서도 Context Precision과 Context Recall은 목표를 통과한 적이 있지만, Faithfulness는 아직 목표에 못 미칩니다.

### 왜 verifier를 기본으로 켜지 않았나요?

답변 생성 후 verifier와 문장 단위 claim checker를 실험했지만, 전체 평가에서 안정적으로 개선되지 않았습니다. 오히려 답변 품질이나 relevancy가 흔들릴 수 있어서 기본값은 꺼두었습니다. 평가에서 좋아 보이는 아이디어라도 실제 수치가 뒷받침되지 않으면 기본값으로 넣지 않는 방향을 선택했습니다.

### 이 서비스가 상담이나 치료를 대체할 수 있나요?

아닙니다. Logos-Log는 치료나 의료 서비스를 대체하지 않습니다. 사용자가 자기 고민을 더 잘 바라볼 수 있도록 연구 기반 성찰 질문을 제공하는 도구입니다. 위기 상황이나 의학적 판단이 필요한 경우에는 전문가의 도움을 받아야 합니다.

## 발표 전 체크리스트

- 데모 질문은 최소 2개를 미리 실행해 응답 품질을 확인합니다.
- Tailscale 데스크톱 백엔드가 켜져 있는지 확인합니다.
- 프론트엔드의 `VITE_API_BASE_URL`이 데스크톱 백엔드를 바라보는지 확인합니다.
- 첫 요청은 모델 워밍업 때문에 느릴 수 있으니 발표 전에 한 번 호출해둡니다.
- 인용 배지, 출처 카드, 출처 모달이 정상 표시되는지 확인합니다.
- Faithfulness가 아직 개선 대상이라는 점을 숨기지 말고, 평가 기반 개선 방향으로 설명합니다.
